# WatTunnel

[English](README.md) | **فارسی**

WatTunnel پورت‌های TCP و UDP را از یک سرور به سرور دیگر روی شبکه‌ی فیلترشده منتقل می‌کند. فقط یک فایل اجرایی Go است و به چیز دیگری نیاز ندارد. ترافیک را می‌تواند از این راه‌ها ببرد:

- **ICMP** (پینگ). حتی وقتی فقط پینگ رد می‌شود هم کار می‌کند.
- **UDP، TCP یا TLS**.
- **WebSocket، HTTP/2 یا gRPC**. این‌ها پشت CDN (مثل Cloudflare) هم کار می‌کنند.

همه‌ی این روش‌ها یک نشست رمزنگاری‌شده‌ی یکسان دارند (ChaCha20-Poly1305 با کلید مشترک) و کنترل ازدحام مخصوص خودشان را دارند. برای همین روی لینک‌های پرافت هم سریع می‌مانند.

## چطور کار می‌کند

</div>

```
users ──► CLIENT (inside server) ══ tunnel (icmp / udp / tcp / tls / ws / grpc …) ══► SERVER (outside server) ──► 127.0.0.1:PORT
```

<div dir="rtl">

- **سرور** روی سرور خارج اجرا می‌شود، یعنی جایی که سرویس اصلی شما (پنل VPN، وب‌سرور و …) گوش می‌دهد.
- **کلاینت** روی سرور ایران اجرا می‌شود. کاربرها به پورت‌های کلاینت وصل می‌شوند و هر اتصال به همان پورت روی `127.0.0.1` سرور خارج می‌رسد.

## نصب

این دستور را روی **هر دو** سرور با کاربر root اجرا کنید (لینوکس با systemd، معماری amd64 یا arm64):

</div>

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/JohnWatsoon/WatTunnel/main/install.sh)
```

<div dir="rtl">

اگر گیت‌هاب روی سرور مسدود است، یک پیشوند میرور جلوی همه‌ی دانلودها بگذارید:

</div>

```bash
WAT_PROXY=https://ghproxy.net/ bash <(curl -fsSL https://ghproxy.net/https://raw.githubusercontent.com/JohnWatsoon/WatTunnel/main/install.sh)
```

<div dir="rtl">

نصب‌کننده این‌ها را اضافه می‌کند: `/usr/local/bin/wattun`، منوی `wattun-manager`، قالب systemd به نام `wattun@.service` و پوشه‌ی `/etc/wattun/`. خودش چیزی را راه‌اندازی نمی‌کند.

## راه‌اندازی تونل

۱. روی سرور **خارج**، `wattun-manager` را اجرا کنید و گزینه‌ی **1) New server tunnel** را بزنید. روش انتقال را انتخاب کنید (اگر فقط پینگ کار می‌کند، ICMP). اگر خواستید، پورت‌هایی را هم که کلاینت اجازه‌ی دسترسی به آن‌ها را دارد مشخص کنید. در پایان، آدرس سرور، روش انتقال و یک **کلید** نمایش داده می‌شود.

۲. روی سرور **ایران**، `wattun-manager` را اجرا کنید و گزینه‌ی **2) New client tunnel** را بزنید. همان روش انتقال، آدرس سرور، کلید و پورت‌هایی را که باید منتقل شوند وارد کنید (مثلاً `443,8080,53/udp`).

۳. وقتی دو طرف به هم وصل شوند، منو `link:true` نشان می‌دهد. از این به بعد کاربرها می‌توانند به پورت‌های سرور ایران وصل شوند.

### منوی مدیریت

| گزینه | کارش چیست |
|---|---|
| New server / client tunnel | راه‌اندازی مرحله‌به‌مرحله. فایل‌های `/etc/wattun/NAME.yml` و `NAME.key` را می‌سازد و سرویس `wattun@NAME` را راه می‌اندازد. |
| Manage a tunnel | وضعیت، آمار زنده، لاگ، اضافه یا حذف پورت (بدون ری‌استارت اعمال می‌شود)، ویرایش کانفیگ، ری‌استارت، توقف، شروع، نمایش کلید و حذف. |
| Update | آخرین نسخه را نصب می‌کند و نسخه‌ی قبلی را برای بازگشت نگه می‌دارد. |
| Roll back | به نسخه‌ی قبلی برمی‌گردد. |
| Uninstall | همه‌ی تونل‌ها را متوقف و WatTunnel را حذف می‌کند. |

میان‌برها: `wattun-manager list`، `wattun-manager update`، `wattun-manager rollback`.

## انتخاب روش انتقال

| روش | کی استفاده شود | نکته |
|---|---|---|
| `icmp` | فقط پینگ رد می‌شود | روی هر دو طرف دسترسی root لازم است. MTU پیش‌فرض (640) را عوض نکنید. |
| `udp` | UDP کار می‌کند | کمترین مصرف CPU و کمترین تأخیر. |
| `tcp` / `tls` | TCP کار می‌کند / ترافیک باید شبیه HTTPS باشد | از چند اتصال هم‌زمان (pool) استفاده می‌کند. |
| `ws` / `wss` / `h2` / `h2c` / `grpc` | پشت CDN یا ریورس‌پراکسی | مقدارهای `sni`، `host` و `path` را در فایل کانفیگ تنظیم کنید. |

حالت معکوس (سرور ایران گوش می‌دهد و سرور خارج وصل می‌شود)، انتقال UDP، FEC، محدودیت ترافیک هر پورت، آمار و همه‌ی کلیدهای کانفیگ در [docs/TECHNICAL.md](docs/TECHNICAL.md) (به انگلیسی) توضیح داده شده‌اند.

## پیکربندی

هر تونل یک فایل در `/etc/wattun/NAME.yml` دارد. تغییر `ports:` ظرف ۳ ثانیه خودبه‌خود اعمال می‌شود. برای بقیه‌ی تغییرها باید سرویس را ری‌استارت کنید (`systemctl restart wattun@NAME`).

</div>

```yaml
mode: client
key-file: /etc/wattun/client.key
carrier: icmp
peer: 203.0.113.10
metrics: 127.0.0.1:19700
ports:
  - 443
  - 53/udp
```

<div dir="rtl">

دستورهای کاربردی:

</div>

```bash
systemctl status wattun@NAME
journalctl -u wattun@NAME -f
curl -s 127.0.0.1:19700/stats
```

## ساخت از سورس

به Go نسخه‌ی ۱.۲۶ یا جدیدتر نیاز دارید.

</div>

```bash
git clone https://github.com/JohnWatsoon/WatTunnel && cd WatTunnel
sh build.sh
go test ./...
sudo bash install.sh
```

## امنیت

- کلید را محرمانه نگه دارید. فایل‌های کلید با دسترسی `600` ساخته می‌شوند.
- بسته‌های افراد غریبه در احراز هویت رد می‌شوند و بدون هیچ پاسخی دور ریخته می‌شوند.
- سرور فقط به `127.0.0.1` و فقط به پورت‌های مجاز وصل می‌شود.
- WatTunnel ترافیک را رمزنگاری و احراز هویت می‌کند، اما وجود تونل را پنهان نمی‌کند و ابزار ناشناس‌ماندن نیست.
