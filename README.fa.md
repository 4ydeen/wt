# 🪁 WatTunnel

**تونل سریع و رمزنگاری‌شده برای انتقال پورت که حتی وقتی شبکه فقط پینگ را رد می‌کند، کار می‌کند.**

WatTunnel دو سرور را به هم وصل می‌کند: سرور **ایران** و سرور **خارج**. هر پورت TCP یا UDP را بین این دو منتقل می‌کند. فقط یک فایل اجرایی است و به هیچ کتابخانه یا برنامه‌ی دیگری نیاز ندارد. راه‌اندازی، مانیتورینگ، عیب‌یابی و آپدیت همه از یک منوی مدیریت انجام می‌شود.

WatTunnel برای یک وضعیت سخت ساخته شده: مسیری که در آن **TCP، UDP، GRE، IPIP و ESP بعد از چند بسته قطع می‌شوند و فقط پینگ (ICMP echo) رد می‌شود**. ابزارهای دیگر این مسیر را مثل یک خط TCP تمیز فرض می‌کنند و از کار می‌افتند. WatTunnel از اول برای همین مسیر طراحی شده است. اگر مسیر شما این‌قدر محدود نیست، همین نشست رمزنگاری‌شده روی UDP، TCP، TLS، WebSocket، HTTP/2 یا gRPC هم کار می‌کند، حتی پشت Cloudflare.

## ✨ ویژگی‌ها

- **وقتی فقط پینگ کار می‌کند، کار می‌کند.** تونل داخل پیام‌های ICMP (echo، timestamp، info یا mask) پنهان می‌شود. اندازه‌ی بسته‌ها ۶۴۰ بایت است، یعنی همان اندازه‌ای که مسیرهای فیلترشده واقعاً می‌رسانند.
- **روی لینک‌های پرافت سریع است.** سرعت بر اساس تأخیر تنظیم می‌شود، پس افت تصادفی سرعت را پایین نمی‌آورد. تأیید انتخابی (selective ack)، جبران سریع بسته‌های گم‌شده و FEC تطبیقی (اختیاری) دارد. ترافیک تعاملی هم قبل از دانلودهای حجیم فرستاده می‌شود.
- **۹ روش انتقال با یک نشست.** `icmp`، `udp`، `tcp`، `tls`، `ws`، `wss`، `h2`، `h2c` و `grpc`. می‌توانید چند روش را با هم ترکیب کنید (bonding)، یا وقتی فقط یک طرف می‌تواند وصل شود از **حالت معکوس** استفاده کنید.
- **یک پروسه برای همه‌ی پورت‌ها.** هم TCP و هم UDP را منتقل می‌کند. پورت‌ها را **بدون ری‌استارت** اضافه یا حذف می‌کنید.
- **سبک.** حدود ۴۰ مگابایت رم مصرف می‌کند. مصرف CPU آن به ازای هر مگابایت، روی مسیر ICMP، یک‌سوم GOST است.
- **رمزنگاری و احراز هویت.** ChaCha20-Poly1305 با کلید مشترک و کلید جداگانه برای هر نشست. بسته‌های نامعتبر بی‌صدا دور ریخته می‌شوند، پس اسکن پورت هیچ پاسخی نمی‌گیرد.
- **کار با آن ساده است.** نصب با یک دستور، اتصال دو سرور با یک **توکن**، داشبورد وضعیت زنده، عیب‌یاب اتصال، ترمیم خودکار، آپدیت و بازگشت به نسخه‌ی قبل.
- **قابل مشاهده.** خروجی JSON در `/stats` شامل RTT، سرعت، افت، تعداد استریم‌ها و کلاینت‌ها. آمار و سهمیه‌ی ترافیک برای هر پورت هم جدا ثبت می‌شود.

## 🤔 چرا WatTunnel؟

| مشکل در مسیر فیلترشده | ابزارهای معمول | WatTunnel |
|---|---|---|
| TCP و UDP بعد از چند بسته قطع می‌شوند | تونل قطع می‌شود یا مدام وصل و قطع می‌شود | از ICMP استفاده می‌کند که قطع نمی‌شود |
| ۰٫۲ تا ۲ درصد افت تصادفی | کنترل ازدحام به سبک TCP با هر افت سرعت را نصف می‌کند | افت را نویز حساب می‌کند، نه ازدحام |
| MTU کوچک (حدود ۶۸۰ بایت) | بسته‌ها تکه‌تکه می‌شوند یا گم می‌شوند | بسته‌ها به‌طور پیش‌فرض ۶۴۰ بایت‌اند |
| یک پروسه برای هر پورت | CPU سرور ایران پر می‌شود | یک پروسه برای همه‌ی پورت‌ها |
| تغییر پورت‌ها | ری‌استارت و قطع همه‌ی کاربرها | فهرست `ports:` هر ۳ ثانیه خودکار دوباره خوانده می‌شود |
| تونل بی‌صدا قطع می‌شود | از کاربرها می‌شنوید | وضعیت زنده، عیب‌یاب و ترمیم خودکار |

### یک توضیح صادقانه: لینک‌های تمیز

روی یک لینک تمیز شبیه‌سازی‌شده (۲۰ میلی‌ثانیه در هر جهت، ۰٫۲ درصد افت، ۱۰۰ مگابیت) همه‌ی تونل‌ها به سقف سرعت لینک می‌رسند. آن‌جا GOST کمی CPU کمتری مصرف می‌کند. اما WatTunnel تأخیر درخواست‌های کوچک را نصف می‌کند (p50 برابر **۴۳ در برابر ۸۳ میلی‌ثانیه**)، چون استریم‌های تعاملی را جلوتر می‌فرستد. جدول کامل: [bench/results-2026-10-09-final.md](bench/results-2026-10-09-final.md). برتری اصلی WatTunnel روی مسیرهای پرافت و فیلترشده است.

> این اعداد از یک مسیر واقعی و یک محیط شبیه‌سازی‌شده‌اند و نتیجه در مسیر شما فرق خواهد کرد. با **Live status** ببینید در عمل چه می‌گیرید.

## 🚀 شروع سریع

به دو سرور لینوکس با systemd (amd64 یا arm64) و دسترسی root نیاز دارید.

**۱. نصب روی هر دو سرور**

</div>

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/JohnWatsoon/WatTunnel/main/install.sh)
```

<details>
<summary>گیت‌هاب روی سرور مسدود است؟</summary>

</div>

```bash
WAT_PROXY=https://ghproxy.net/ bash <(curl -fsSL https://ghproxy.net/https://raw.githubusercontent.com/JohnWatsoon/WatTunnel/main/install.sh)
```

<div dir="rtl">

می‌توانید `wattun-linux-amd64`، `install.sh` و `wattun-manager` را هم از صفحه‌ی [Releases](https://github.com/JohnWatsoon/WatTunnel/releases) دانلود کنید و روی سرور بگذارید. فایل اجرایی را در پوشه‌ی `dist/` کنار `install.sh` قرار دهید و `bash install.sh` را اجرا کنید.
</details>

در پایان نصب، از شما می‌پرسد این سرور کدام طرف است.

**۲. سرور خارج.** گزینه‌ی **Kharej** را انتخاب کنید. روش انتقال (اگر فقط پینگ کار می‌کند `icmp`) و پورت‌های سرویس‌تان را مشخص کنید. در پایان یک **توکن اتصال** نمایش داده می‌شود:

</div>

```
wat1:aWNtcHwyMDMuMC4xMTMuMTB8a1E3...
```

<div dir="rtl">

**۳. سرور ایران.** گزینه‌ی **Iran** را انتخاب کنید، توکن را paste کنید و پورت‌هایی را که کاربرها به آن‌ها وصل می‌شوند وارد کنید (مثلاً `443,2053,53/udp`). منو منتظر برقراری اتصال می‌ماند و این را نشان می‌دهد:

</div>

```
✔ Tunnel 'iran' is running.
✔ CONNECTED (RTT 41.3 ms)
✔ Users can now connect to this server on: 443,2053,53/udp
```

<div dir="rtl">

از این به بعد کاربرها به IP سرور ایران وصل می‌شوند. هر پورت به همان پورت روی `127.0.0.1` سرور خارج می‌رسد.

</div>

```
users ──► Iran :443 ══ WatTunnel (icmp / udp / tls / wss …) ══► Kharej ──► 127.0.0.1:443 (your service)
```

## 🧭 منوی مدیریت

دستور `wattun-manager` را اجرا کنید:

</div>

```
╔══════════════════════════════╗
║        WatTunnel Manager     ║  wattun 1.8.0
╚══════════════════════════════╝
  iran         Iran   icmp  CONNECTED     rtt 41ms   streams 37   ↓12.4 GB ↑1.9 GB

  1) Kharej setup  (outside server - tunnel server)
  2) Iran setup    (inside server - tunnel client)

  4) Live status monitor
  5) Settings (auto-heal)
  6) Update WatTunnel      7) Roll back      8) Uninstall
```

| **وضعیت** | هر تونل `CONNECTED`، `DISCONNECTED` یا `STOPPED` نشان داده می‌شود، همراه با RTT، تعداد استریم‌ها، حجم ترافیک و تعداد کلاینت‌های وصل. |
| **مانیتور زنده** | داشبوردی که هر ۲ ثانیه به‌روز می‌شود. |
| **عیب‌یابی** | بررسی مرحله‌به‌مرحله: روشن بودن سرویس، دسترسی پینگ یا TCP به خارج، وضعیت لینک، پورت‌هایی که گوش می‌دهند، پاسخ دادن سرویس شما روی خارج، و خطاهای اخیر در لاگ. برای هر خطا علت احتمالی را هم می‌گوید. |
| **لاگ** | ۱۰۰ خط آخر، دنبال‌کردن زنده، فقط خطاها، یا از آخرین شروع. |
| **پورت‌ها** | اضافه و حذف پورت بدون ری‌استارت و بدون قطع شدن کاربرها. |
| **توکن و کلید** | نمایش دوباره‌ی توکن، عوض کردن کلید (روی خارج)، یا paste کردن توکن جدید (روی ایران). |
| **ترمیم خودکار** | اگر لینک تونل ایران ۳ دقیقه قطع بماند، یک تایمر systemd آن را ری‌استارت می‌کند. این ری‌استارت‌ها با نام `wattun-heal` در لاگ ثبت می‌شوند. |
| **آپدیت و بازگشت** | آخرین نسخه را بعد از بررسی SHA-256 نصب می‌کند و نسخه‌ی قبلی را نگه می‌دارد تا با یک قدم برگردید. |

میان‌برهای خط فرمان:

</div>

```bash

wattun-manager test NAME       # connection doctor
wattun-manager logs NAME       # follow the log
wattun-manager token NAME      # print the Kharej token
wattun-manager update | rollback
```

## 🛰 انتخاب روش انتقال

| روش | کی استفاده شود | توضیح |
|---|---|---|
| `icmp` | **فقط پینگ رد می‌شود.** | دسترسی root لازم است (منو تونل را با root اجرا می‌کند). اگر echo مسدود است، `icmp-type` را روی `timestamp`، `info` یا `mask` بگذارید. |
| `udp` | UDP کار می‌کند. | کمترین تأخیر و کمترین مصرف CPU. |
| `tcp` | TCP معمولی کار می‌کند. | از ۸ اتصال هم‌زمان استفاده می‌کند. |
| `tls` | ترافیک باید شبیه HTTPS باشد. | TLS 1.3. اگر گواهی ندهید، از گواهی خودامضا استفاده می‌کند. با `tls-pin` می‌توانید گواهی را pin کنید. |
| `wss` | پشت **Cloudflare** یا CDN دیگر. | در راه‌اندازی خارج، دامنه‌تان را وارد کنید. پراکسی Cloudflare (ابر نارنجی) را روشن کنید و SSL را روی *Full* بگذارید. |
| `ws` / `h2c` | CDN روی پورت ۸۰، یا ریورس‌پراکسی‌ای که TLS را خودش انجام می‌دهد. | تا پراکسی رمزنشده می‌رود، اما خود نشست همچنان رمزنگاری‌شده است. |
| `grpc` / `h2` | CDN یا پراکسی‌ای که gRPC یا HTTP/2 را ترجیح می‌دهد. | |

مطمئن نیستید؟ روی مسیرهای خیلی فیلترشده با `icmp` شروع کنید و پشت Cloudflare با `wss`. حالت معکوس، bonding و تنظیمات پیشرفته در [docs/TECHNICAL.md](docs/TECHNICAL.md) (به انگلیسی) توضیح داده شده‌اند.

## ⚙️ پیکربندی

هر تونل یک فایل خوانا در `/etc/wattun/NAME.yml` دارد و systemd آن را با نام `wattun@NAME` اجرا می‌کند. کلیدهای این فایل همان فلگ‌های خط فرمان‌اند.

</div>

```yaml
# /etc/wattun/iran.yml
mode: client
key-file: /etc/wattun/iran.key
carrier: icmp
peer: 203.0.113.10
metrics: 127.0.0.1:19700
ports:
  - 443
  - 2053
  - 53/udp
```

<div dir="rtl">

- تغییر `ports:` ظرف ۳ ثانیه اعمال می‌شود. برای بقیه‌ی تغییرها باید `systemctl restart wattun@NAME` را اجرا کنید.
- روی خارج، `ports:` فهرست پورت‌های محلی‌ای است که کلاینت‌ها اجازه‌ی دسترسی به آن‌ها را دارند. اگر آن را ننویسید، همه‌ی پورت‌ها مجازند.
- همه‌ی کلیدها (محدودیت ترافیک هر پورت، FEC، سقف سرعت `max-mbps`، MTU، TLS، هدرهای CDN و …) در [docs/TECHNICAL.md](docs/TECHNICAL.md#config-file) آمده‌اند.

| مشکل | علت احتمالی و راه‌حل |
|---|---|
| `DISCONNECTED` بدون هیچ خطایی | کلید یا روش انتقال در دو طرف فرق دارد. توکن را دوباره روی ایران paste کنید. برای ICMP، بررسی کنید که `ping` از ایران به خارج جواب می‌دهد. |
| ICMP: پینگ‌های کوچک جواب می‌دهند ولی تونل گیر می‌کند | مشکل MTU است. همان مقدار پیش‌فرض ۶۴۰ را نگه دارید. |
| `tcp`، `tls` یا `ws` اصلاً وصل نمی‌شوند | این روش در مسیر شما فیلتر است یا پورت بسته است. `icmp`، یا `wss` پشت CDN را امتحان کنید. |
| تونل وصل است ولی سایت‌ها باز نمی‌شوند | روی `127.0.0.1:PORT` سرور خارج چیزی گوش نمی‌دهد. عیب‌یاب همین را بررسی می‌کند. |
| خطای `address already in use` | برنامه‌ی دیگری پورت را گرفته است: `ss -ltnp \| grep :PORT` |
| پیام `restart needed for KEY` در لاگ | فقط `ports:` بدون ری‌استارت اعمال می‌شود. تونل را ری‌استارت کنید. |

## 🔐 امنیت

- **کلید مشترک.** هیچ‌وقت روی شبکه فرستاده نمی‌شود. هر نشست کلید خودش را از آن می‌سازد و هر بسته با ChaCha20-Poly1305 و یک nonce که هرگز تکرار نمی‌شود رمز می‌شود.
- **اول احراز هویت.** بسته‌ای که احراز هویت نشود هیچ وضعیتی نمی‌سازد و هیچ پاسخی نمی‌گیرد، پس اسکن و تکرار بسته‌ها چیزی نمی‌بینند.
- **دسترسی حداقلی.** سرور خارج فقط به `127.0.0.1` و فقط به پورت‌های مجاز وصل می‌شود.
- **نگهداری کلیدها.** دسترسی `/etc/wattun` روی `700` و فایل‌های کلید روی `600` است. **توکن شامل کلید است**، پس آن را فقط از راه امن به اشتراک بگذارید.
- **محدوده.** WatTunnel ترافیک شما را رمزنگاری و احراز هویت می‌کند، اما وجود تونل یا آدرس سرورها را پنهان نمی‌کند و ابزار ناشناس‌ماندن نیست.

## ❓ سؤالات رایج

<details><summary><b>روی هر دو سرور یک چیز نصب می‌شود؟</b></summary>
بله. یک فایل اجرایی است و نقش هر سرور (خارج یا ایران) در منو انتخاب می‌شود.
</details>

<details><summary><b>یک سرور خارج می‌تواند به چند سرور ایران سرویس بدهد؟</b></summary>
بله. همان توکن را روی هر سرور ایران وارد کنید. هر کلاینت نشست و کلید جداگانه‌ی خودش را دارد.
</details>

<details><summary><b>می‌توانم چند تونل روی یک سرور داشته باشم؟</b></summary>
بله. هر تونل اسم، فایل کانفیگ و سرویس systemd جداگانه دارد. مثلاً یک تونل ICMP و یک تونل WSS به‌عنوان پشتیبان.
</details>

<details><summary><b>اضافه کردن پورت کاربرها را قطع می‌کند؟</b></summary>
نه. تغییر پورت‌ها بدون ری‌استارت اعمال می‌شود. فقط تغییر روش انتقال، آدرس یا کلید ری‌استارت لازم دارد.
</details>

<details><summary><b>با چه چیزهایی کار می‌کند؟</b></summary>
با هر چیزی که روی TCP یا UDP کار کند: Xray، V2Ray، Sing-box، OpenVPN، WireGuard (به‌صورت UDP)، SSH، پنل‌های وب و بازی‌ها.
</details>

<details><summary><b>چه چیزی روی سرور خارج باید باز باشد؟</b></summary>
برای ICMP، سرور باید به پینگ جواب بدهد، پس ICMP را در فایروال دیتاسنتر مسدود نکنید. برای روش‌های دیگر، فقط همان پورتی که انتخاب کرده‌اید باید باز باشد.
</details>
